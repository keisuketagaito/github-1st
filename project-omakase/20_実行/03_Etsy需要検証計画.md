## 0. なぜこの計画があるのか

ユーザーの意図は当初から一貫して **「訪日客向けに、日本の旅行を楽しむためのコンテンツを売る」** ことだった（レシピ動画は集客のフック）。v2で「レシピ商品が主軸・訪日向けは売上の4%」という設計になったのは、この意図からのずれであり、2026-10-11に**収益の主軸を「訪日客向けの食×旅デジタルガイド」に戻した。**

あわせて、販路に **Etsy** を選んだ。noteに最も近い性質（**プラットフォーム内で検索されて売れる**）を持つため、**フォロワーゼロでも販売を始められる**。これまでの計画はすべて「3〜5ヶ月かけて集客してから販売」だったが、Etsyなら**第2週に1点出品して、見知らぬ人が本当にお金を払うかを確かめられる。**

> 7月27日の計画開始から2ヶ月半で戦略は4回改訂されたが、実行はDay 1（就業規則確認）で止まっている。ここから先は、**計画を磨くより市場に出して反応を見るほうが確実に速い。** この6週間の目的はそれだけである。

**すべて店舗訪問なしで作れる。** 特定の店を推薦するのではなく、「仕組み」と「言い方」を教える。これにより、店の閉店・価格改定で商品が陳腐化しにくい。

**3点の価格を$5.99／$7.99／$11.99に分けているのは、価格感度も同時に見るため。**（2026-10-20 競合調査を受けて端数価格に調整）

P1の詳細な構成・日本語カード・出品文の下書きは `../90_商品/01_HowToOrderFoodInJapan/構成案.md` に作成済み。

### P2の安全上の注意（必読）

食物アレルギーは**命に関わる**。P2では以下を守る。

- 「この商品は安全」と**特定の商品・店を保証しない**（原材料は予告なく変わる）
- 教えるのは「表示の読み方」と「伝え方」まで
- 冒頭と各ページに免責を明記：**医療上の助言ではない。重度のアレルギーの方は医師に相談し、必ず店員に直接確認すること**
- 日本の食品表示制度（表示義務のある特定原材料の品目など）は**消費者庁の最新情報で確認してから書く**

## 5. 計測と判定ルール

### 計測する数字（Etsyの「ショップ統計」で毎週日曜に確認）

| 指標 | 意味 |
| --- | --- |
| 訪問数（商品ごと） | 検索で見つけてもらえているか |
| お気に入り数 | 興味はあるか |
| 注文数 | **お金を払ったか**（最重要） |
| 転換率（注文÷訪問） | 商品ページが機能しているか |
| レビュー内容 | 何に価値を感じたか（次の商品の仕様になる） |

### 判定ルール（Week 7、または各商品の訪問が300を超えた時点）

| 状況 | 判断 |
| --- | --- |
| **1点でも5本以上売れた** | **需要あり。** そのテーマで5点追加し、バンドル化する。SNS（A/B/C）はその商品への集客装置として再設計する |
| 訪問300超・販売0 | 商品ページの問題（サムネイル・価格・説明文）。**1回だけ**改訂して2週間様子を見る |
| 6週で訪問100未満 | 検索需要かキーワードの問題。タイトル・タグを改訂し、Etsy広告を1日$1〜2で2週間試す |
| 改訂後も3点すべて0本 | **Etsy単体では成立しない。** 自社集客（SNS→Gumroad）前提の計画に戻す。これも「答えが出た」という成果 |

> 判定の閾値（5本・300訪問・100訪問）は初期の目安です。Etsyの新規ショップは最初の数週間は露出が少ない傾向があるため、Week 7時点で訪問が伸び続けているなら、判定を2週間延ばして構いません。

## 6. 制作ルール（AI運用設計の原則をそのまま適用）

> **AIに任せてよいのは「変換」。任せてはいけないのは「一次情報」。**

この商品の一次情報は **「日本在住のネイティブとして知っていること・確認したこと」** である。

| AIがやってよいこと | 人間（ユーザー）が必ずやること |
| --- | --- |
| 構成案、英文の下書き・校正、レイアウト、イラスト生成 | **日本語フレーズの確認**（自然か、実際に通じるか） |
| 説明文・タグの候補出し | **事実の確認**（券売機の仕組み、表示制度、相場など） |
| 競合調査の要約 | どのテーマを出すかの判断 |

- 構成案の **`要確認`** 印がついた箇所は、確認するまで出品しない
- **特定の店名を推薦しない**（陳腐化と、店舗訪問への逆戻りを避ける）
- 写真を使う場合は自分で撮ったもののみ。**イラストはAI生成可**（開示する）
