## 0. 大原則

> **AIに任せてよいのは「変換」。任せてはいけないのは「一次情報」。**

- **一次情報** ＝ 実際に代替品で作った、食べた、その味が成立した、その食材が近所で買えた、この代替は失敗した。
  これが本事業の差別化そのものであり、**AIには原理的に作れない。**
- **変換** ＝ 検証メモの構造化、翻訳、台本化、要約、バリエーション生成、組版。
  ここは人間より速く安い。**ここを人間がやっている限り、調理・検証の時間が消える。**

この線引きは倫理の話ではなく、**事業設計の話**である。AIに一次情報を書かせた瞬間に、無料のレシピサイトや生成AIと区別がつかなくなり、$24の根拠が消える。生成AIは「作って食べていない」から代替食材の提案が実際には失敗する——そこを実検証で埋めるのが本事業なので、AIに検証結果を捏造させれば競合との差がそのまま消える。同時に、YouTubeが収益化の判定軸に置く「オリジナリティ」と「編集の労力」の要件とも、この線引きは完全に一致する。

**この線を守る限り、AIをどれだけ使っても事業は強くなる。越えた瞬間に壊れる。**

## 2. AIを使わない工程（意図的に人間が行う）

| 工程 | 理由 |
| --- | --- |
| **献立設計・調理・実食** | 事業の核。ここを外注・自動化した瞬間に差別化が消える |
| **代替食材の検証** | 「みりんを◯◯で代替して味が成立した」「この代替は失敗した」は、実際に作って食べないと分からない。AIの推測は誤情報になる |
| **写真・動画の撮影** | AI生成画像を料理写真として使うことは、事実の捏造にあたる |
| **返金対応・クレーム対応** | 信頼の回復は人間の仕事 |
| **タイアップの商談** | 関係構築が資産 |
| **有料商品の最終校閲** | 返金率に直結する |

## 3. 週次AIパイプライン（これが運用の背骨）

まとめ撮り1回（3〜4品）から公開までを、以下の流れで回す。**プロンプトは `03_AIプロンプト集.md` の番号に対応。**

> **2アカウント運用でも週15時間に収まる理由**：まとめ撮り・検証・構造化（＝一次情報の工程）は**1回で両アカウント分を賄う**ため増えない。増えるのは「Account B用の角度替え編集」だけで、これは字幕・翻訳・素材を流用した軽量編集（週+1.0h）。増えた分は他工程のAI圧縮（メール・DM）で吸収する。時間配分の詳細とフォールバック（超えたらBを週3本へ）は `../00_戦略/03_媒体戦略.md` 4章。

### 事前（金曜まで） — 献立設計・買い出し（P-01）

```
[AI] P-01  同じ調味料を使い回せる3〜4品の献立案＋買い出しリスト・買い出し先
        ↓
[人間]     作る品を最終決定し、週末に買い出し
```

### 土曜／日曜 — まとめ撮り（5.0h）

```
[人間] 1セッションで3〜4品を並行調理・撮影・実食
  ├─ 撮影：定点＋手元カメラを固定したまま品を入れ替える
  ├─ 代替食材を実際に代替品で作って食べ、成立するか検証する ← 事業の核
  └─ 各品の「失敗しやすい点」と代替検証の結果を、その場で音声メモに録る
      → 後日は必ず忘れる。その場で録ることが唯一の担保
```

### 日曜夜 — 構造化（30分）

```
[AI] P-02  音声メモ（文字起こし）→ レシピ標準9項目の構造化データ
        ↓
[人間]     事実確認して レシピデータベース.xlsx に追記（1品2分）
        ↓
[AI] P-03  代替食材の検証結果を 3列表記（日本の材料／海外で買えるもの／代替可）へ整形
        ↓
[人間]     検証していない代替は載せない。実検証した結果だけを確定させる ← 重要
```

### 火曜夜 — 制作（2.0h）

```
[AI] P-04  1品につきフック10案（Account A＝置き換え系／Account B＝「なぜ」・文化系の両方）→ 人間が各1つ選ぶ
[AI] P-05  選んだフックで45秒台本 → 人間が言い回しを直す
[人間]     Account A の撮影素材を編集（1本25〜30分 × 5本）
[人間]     同素材から Account B 用の角度替え版を軽量編集（字幕・翻訳・BGMを流用し、テロップ／ナレーションの切り口だけ差し替え。週3本）
[AI] P-06  文字起こし → 英語字幕（表現をネイティブ化。A/B共通で流用）
```

**Account B の編集は「新規制作」ではなく「Aの編集済み素材の再編集」。** ここが重いと感じたら（1本30分超）、迷わず B を週3本へ落とす（`../00_戦略/03_媒体戦略.md` 4章のフォールバック）。

### 木曜夜 — 仕上げ（2.0h）

```
[AI] P-07  キャプション・ハッシュタグ・投稿時間
[AI] P-08  カルーセル1本の構成とコピー
[人間]     Canvaの型に流す → Pinterestへも転用
[AI] P-09  週次メールの下書き → 人間が実体験を挿入（ここが本体）
```

### 日曜夜 — 締め（1.0h）

```
[AI] P-10  コメント・DMの返信下書き → 人間が確認して送信
[AI] P-11  週次数値の要約と異常値の指摘 → 人間が意思決定
[人間]     翌週の献立（使い回せる調味料の組み合わせ）を確定
```

### Account C の週次パイプライン（火・金の週2本／+3.0h・完全な追加分）（2026-09-20 Account C追加）

A/Bのまとめ撮りとは別枠。**自炊しないため撮影素材の共通化が効かない。** 火・金に1本ずつ出す。

```
[人間] C-1  トレンドリサーチ（1.0h）：りゅうじ・クラシル・デリッシュキッチン等で
            何が伸びているかを収集。扱うトレンドを選定し、元クリエイター・出典を特定する
        ↓
[AI]  C-2  事実レベルの要約のみ（0.5h）：視聴回数の傾向・大まかな特徴を要約させ、
            「なぜ流行っているか」の仮説を出させる
            ★ 元動画の台本・構成・言い回しはAIに読み込ませない（4章の線引き）
        ↓
[人間] C-3  リアクション・解説を自分の言葉で撮影（0.5h）。「作れます」ではなく
            「なぜ今流行っているか」を伝える。「検証済み」とは一切言わない
        ↓
[AI]  C-4  字幕整形・キャプション下書き・ハッシュタグ（1.0h の一部）
        ↓
[人間]     編集し IG Reels＋TikTok へ。★ 画面内クレジット表示＋キャプションのクレジット＋
            リンクの3点セットを必ず入れる（`02_マーケティング運用マニュアル.md`）
```

**Cで守る鉄則**：①元クリエイターを画面内・キャプション両方でクレジットしリンクを貼る、②「検証済み／テスト済み」と一切謳わない（Cは自分で作っていない。A/Bの検証済みと混同させない）、③AIには事実の要約までしかさせない。実測が3h/週を超える場合は週2本→週1本へ落とす（`../20_実行/01_90日実行計画.md` Week 2）。

## 4. AI運用の禁止事項（違反すると事業が壊れる）

| # | 禁止 | 何が起きるか |
| --- | --- | --- |
| 1 | **作って食べていないレシピ・検証していない代替食材をAIに書かせる** | ハルシネーションで、実際には失敗する代替（例：みりんの誤った代替）や成立しない味付けが混入する。**商品の根幹が壊れ、1件の失敗報告で全体の信用を失う** |
| 2 | **AI生成画像を料理写真として使う** | 事実の捏造。読者・タイアップ先からの信頼を失い、タイアップの道が閉じる |
| 3 | **英語の最終出力を無検証で有料商品に載せる** | 英文品質は返金率に直結する |
| 4 | **AIに「おすすめレシピ60選」を出させて、それを商品にする** | 無料レシピサイト・生成AIと区別がつかず、$24の根拠が消える |
| 5 | **テンプレートの使い回しだけで量産する** | YouTubeの収益化ポリシー（オリジナリティ・編集の労力）に抵触する |
| 6 | AI音声・AI画像を使いながら明示しない | 規約違反。使う場合は概要欄に明記する |

**1と4は、この事業における最重要の禁止事項。** 楽をしたくなる瞬間に必ず誘惑が来るので、明文化しておく。

### 4.1 Account C における「許可される紹介」と「禁止される代替生成」の線引き（2026-09-20 Account C追加）

Account C は日本のトレンドレシピを紹介・解説する（`../00_戦略/03_媒体戦略.md` 0.6節）。ここで**将来読み返したときに迷わないよう、許可と禁止の境界を明確に定義する。** 一言でいえば——**「事実を要約して自分の言葉でリアクションする」のは許可。「元動画そのものをAIで作り直す」のは禁止。**

| | 内容 | 判定 |
| --- | --- | --- |
| **許可される（トレンド紹介）** | 元クリエイターを画面内・キャプション両方でクレジットしリンクを貼った上で、「何が・どれだけ伸びているか」「大まかな特徴」「なぜ流行っていそうか」といった**事実レベルの情報をAIに要約させ**、それを土台に自分の言葉でリアクション・解説する | ○ |
| **禁止される（代替生成）** | 元動画の**台本・構成・言い回し・調理手順の並びをAIに読み込ませて、それを再現・言い換え・代替生成し、自分のコンテンツとして出す**。実質的に他者の動画をAIで作り直す行為 | ✕ |

**禁止側は、この表の禁止事項1・4に正面から該当する。**
- **禁止事項4**（AIに出させたレシピ集をそのまま商品・コンテンツにする）に該当——元動画の構成をAIで再生成したものは「作って食べていない・独自の一次情報がない」出力であり、無料レシピサイト・生成AIと区別がつかない。
- **禁止事項1**（作って食べていない・検証していないものをAIに書かせる）にも該当——Cは自炊しないため、元動画の手順をAIで再構成すれば、検証を経ない調理情報を自分が作ったかのように流すことになる。加えて依拠性の著作権リスク（意思決定ログ 2026-09-20）とYouTubeのAI量産コンテンツ収益化ポリシー（禁止事項5）にも触れる。

**線引きの実務的な判定基準**：「元クリエイターのクレジット・リンクを外したら、このコンテンツは成立するか？」——成立してしまうなら、それは紹介ではなく代替生成であり、禁止側に落ちている。クレジットとリンクが構造的に不可欠であること（＝あくまで"紹介"であること）が、許可側に留まる条件である。

## 5. AIが出した情報の検証ルール

AIの出力は「下書き」であって「事実」ではない。以下は**必ず人間が一次ソースで確認する**。

| 種別 | 検証方法 |
| --- | --- |
| 代替食材で味が成立するか | **実際に代替品で作って食べる**（推測は不可） |
| その代替食材が海外で買えるか | 一般スーパー／アジア系食料品店／オンラインの取り扱いを確認 |
| 分量・計量（g ⇄ cup/oz の実務換算） | 実際に量って調理した値を使う |
| 手順で失敗しやすい点 | **自分で作って詰まった点**を記録（最も保存される要素） |
| ベジ／ハラル／グルテンフリー対応 | 対応版を実際に作って成立を確認 |
| 保存・作り置きの可否 | 実際に保存して状態を確認 |
| 英語表現（料理名・調理用語） | ネイティブチェック（有料商品は必須） |

**「AIがそう言った」は、掲載の根拠にならない。**

## 7. AI活用の成熟度ロードマップ

| 段階 | 時期 | 状態 |
| --- | --- | --- |
| **L1：下書き生成** | 1〜3ヶ月目 | 都度プロンプトを書いて、台本・キャプションの下書きを作らせる |
| **L2：型の固定** | 4〜6ヶ月目 | `03_AIプロンプト集.md` を確定させ、毎回同じプロンプトを使う。出力の品質が安定する |
| **L3：パイプライン化** | 7〜12ヶ月目 | 検証メモ→構造化→台本→字幕までを一連の流れで回す。所要時間が読めるようになる |
| **L4：外注との併用** | 13ヶ月目〜 | AIで下書き、外注が仕上げ、自分は調理・検証と判断のみ。**ここで週15時間の壁を超えられる** |

**L2に到達しないうちに投稿本数を増やさないこと。** 型が固まる前に量を増やすと、品質のばらつきがそのまま残る。

## 8. AI前提の運用が失敗するとしたら

| 失敗の形 | 兆候 | 対処 |
| --- | --- | --- |
| AIの出力をそのまま出し、内容が薄くなる | 保存率が3%を下回り続ける | 一次情報の密度を上げる。AIの使用範囲を「変換」に戻す |
| 調理・検証時間がAI作業に食われる | 月の検証済みレシピ数が伸びない | AI工程を削り、まとめ撮り・検証を優先する。**調理・検証は最後まで守る** |
| プロンプトが毎回違い、品質が安定しない | 出力の手直し時間が増えている | L2（プロンプト集の確定）に戻る |
| ハルシネーションが商品に混入 | 読者から「その代替食材では作れなかった」の指摘 | 5章の検証ルールを再徹底。該当レシピを即時改訂して全購入者に配信 |

**最後の項目が起きたときの対応速度が、この事業の信頼を決める。** 指摘から48時間以内に改訂版を配信すること。それができるなら、むしろ「読者の失敗報告で更新され続けるレシピ集」という差別化の証明になる。
