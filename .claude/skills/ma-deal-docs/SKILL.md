## 最初に読むこと

**成果物ごとに、テンプレート・部品・仕様書・品質基準が決まっている。着手前に該当行の仕様書を読む。**

描画チェックで出た不具合の一覧）。**新しい概要書はこの水準以上で作る。**

## このスキルの中心的な考え方

案件資料は**案件マスター（Excel）が唯一の数値のソース**であり、パワポ・ワードはその表示層にすぎない。

実務でよく起きる事故は「概要書の財務ハイライトだけ直して、評価書の正常収益力が古いまま」「会社分割スキームを変えたのに分割後BSが更新されていない」といった**資料間の数値不整合**である。買手は必ず両方を突き合わせて読むので、1箇所の不整合が資料全体の信頼を落とす。

依頼が「概要書のこのページだけ直して」であっても、その数字がマスター由来なら**先にマスターを直す**。マスターを飛ばしてパワポだけ直すと、次に誰かがマスターから貼り直した瞬間に修正が消える。

## 品質基準（この水準で作る）

概要書は「資料を並べたもの」ではなく、**受領資料をすべて突き合わせて論点を掘り出し、買手が買いたくなる形に編集したもの**である。次の水準を満たすまで納品しない（チェック項目は `references/quality-checklist.md`）。

1. **受領資料を全部読んで突き合わせる。**決算書・内訳書・試算表・順位表・謄本・課税明細・共同担保目録・契約書・台帳・聴取メモを相互に照合し、食い違いを論点として拾う。差異は「未登記」「転記漏れ」「名義の相違」「担保の付け替え」など、実務上の意味に翻訳して書く
2. **すべての数字の出所をたどれるようにする。**数字はマスターに入れ、概要書の注記に出典を書く。合計は必ず検算する。依頼者が記入した部分も科目ごとに前期と比べて行ずれがないか確かめる
3. **案件ごとに構成を設計する。**標準構成をなぞらず、その会社の魅力と論点に合わせてページを足し引きする（`im-structure.md`「案件ごとの構成の決め方」、`im-design.md` §5）
4. **事実は隠さず、プラスを先に書く。**マイナスは「一過性」「手当て可能」「手続き中」とセットにする。未確認は「要確認」、推測は「〜と推察」
5. **実物で検証してから納品する。**全頁を描画して目視（`scripts/render_check.py`）、表の構造チェック、旧版との差分、数字の波及先の検索まで行う（Step 6）
6. **依頼の意図を汲んで一歩先まで出す。**聞かれたことに答えたうえで、その判断に必要な論点（新規借入・取引先依存・税務・スキームへの影響）と、残っている要確認事項を添える

## 企業概要書の標準フロー（鶴岡中央青果261027で確立）

| # | 作業 | 道具 | 守ること |
|---|---|---|---|
| 1 | 受領資料をすべて読み、データ化する | Drive `read_file_content`、PDFは `pdftotext`、謄本は `registry_parse.py` | 大きいPDFは結果ファイルから本文を抜いて集計。別案件の資料が混ざっていないか目視 |
| 2 | **公式マスターを埋める** | `assets/案件マスター_公式テンプレート.xlsx`（依頼者記入途中のマスターがあればそれを起点） | 財務入力（3期＋進行期）→VR→→IM→の順。1期目・空行は非表示。手順と不具合は `im-design.md` §7 |
| 3 | 再計算・検算 | soffice＋`inject_cache.py`（またはコピーに `recalc.py`） | 数式エラー0・チェックセルTRUE・調整後EBITDAの3者一致 |
| 4 | テンプレートから頁構成を作る | `im_builder.open_template()` `keep_slides()` `duplicate_slide()` `strip_red_banners()` `fix_broken_pictures()`、`im_paste.remove_watermark()` | 業種の核の頁を足し、使わない頁を消す。各頁の見本の表・画像は `clear_body()` か `remove()` で消してから貼る。報酬体系頁は消さない |
| 5 | **表はマスターの貼付範囲を貼る** | `im_paste.paste_range()`（公式マスターは fscale/hscale で縮める） | パワポに数字を打たない。リード文・Commentの数字もマスターから読む |
| 6 | 文章を書く | `set_lead()`（2行以内）、テンプレートのComment枠に `fill_comment()`、図解は `im_builder` の部品 | ≪見出し≫＋・本文。「だから何なのか」を書く |
| 7 | 描画して直す | `scripts/render_check.py` | 折返し・重なり・字幕3行・表のずれがなくなるまで繰り返す（通常3〜4周） |
| 8 | 検査・納品 | `validate.py --original`、`check_confidential.py`、`quality-checklist.md` | pptx・pdf・マスターを案件フォルダへ保存しコミット・プッシュ。要確認事項と依頼者の判断事項を報告 |

**表の作り方の優先順位：**数字を含む表は必ずマスターの貼付範囲（`paste_range`）。数字を含まない表（許認可・沿革・補足等）もマスターに置いて貼るのが原則。
`im_builder.house_table()` で行データから直接組むのは、マスターに置く意味のない補助的な表だけに限る。

## 全体ワークフロー

### Step 1. 受領資料の棚卸しと転記

決算書・登記簿・給与台帳・取引先実績・契約書等を読み、案件マスターの該当シートへ転記する。
シート構成と転記先の対応は `references/master-sheets.md` を読むこと。

- **数値は円単位で入力する。**表示形式が千円単位に設定済みのため、千円で入れると1000倍ずれる
- **文字は游ゴシック、数字はArial、細かい備考は游ゴシック Medium。**タイトル・合計欄は太字
- **確認できていないことは「要確認」と書く。**推測で埋めない。後工程（評価書のコメント、ヒアリング項目一覧）でそのまま使える資産になる
- 転記後は必ず**借貸一致とPL整合のチェックセル**（`EXACT()` 行）が TRUE であることを確認する
- **不動産がある案件は、課税明細・謄本・共同担保目録・賃貸借契約書を突合する。**手順は `references/real-estate.md`、謄本PDFは `scripts/registry_parse.py`
- 資料が後から追加で届いたら、既存の区分・集計を見直す
- **グラフ入りのマスターを openpyxl で保存すると、グラフのスタイル・図形の一部が落ちる。**セルを少し直すだけなら `scripts/xlsx_xml.py`（または `references/xledit.py`）でXMLを直接編集する。IMシートの組み直しなど大きな変更を openpyxl で行う場合は、`株式価値` シートのグラフが残っているかを保存後に確認する
- CJKフォント非埋め込みのPDFが真っ白になる場合は `apt-get install -y poppler-data` で `pdftotext -layout` が使えるようになる（壊れたPDFと早合点しない）

### Step 2. 評価パート（VR→ セクション）の作成

時価純資産と正常収益力を算定する。**評価方法の正本は専用スキル `ma-valuation`**（`.claude/skills/ma-valuation/SKILL.md`）。
マスター側の操作と評価書パワポの組み方は `references/valuation.md`。

- **非流動性ディスカウント（EV×30%）は案件の状況に応じて判断する**（標準形は掛けない＝EV＋ネットキャッシュ。状況によっては掛ける）。公式テンプレートのEVシート `K9` で率を切り替える。適用の有無と理由を評価書に明記し、既存案件の判断は依頼者の指示なく変えない
- 正常化調整（役員報酬・顧問料・社保・賞与・寄付金・経常的な営業外収益）は修正PLの「正常化調整の前提」ブロックに置き、修正SGA・修正PL・PLハイライトはそこを参照する
- 評価書のパワポは `assets/株式価値評価書_テンプレート.pptx` を複製して作る（`vr_builder.open_vr_template()`）

### Step 3. IMパート（IM→ セクション）の作成

**マスターは当社の公式フォーマット（M&A承継機構 案件マスター 0925版）を使う。**ユーザーから記入途中の公式マスターを渡されたら、それを起点に全シートを埋める（独自形式のマスターを別に作らない）。
会社概要・PLハイライト・BSハイライト・取引先・仕入先・従業員等を、**概要書の表と同じ行・列・書式の「貼付範囲」**として組み、
範囲内の数値は財務入力→・VR→を数式で参照する。各シートのA1（公式シート）／A2（追加シート）に貼付範囲と貼り先ページを明記する。
列の使い方・非表示の運用・倍率・テンプレートの不具合は `references/im-design.md` §7、書式キットは `scripts/master_im_style.py`。
組み終えたらLibreOfficeで再計算し、`scripts/inject_cache.py` で値を書き戻す（書式を壊さないため）。

### Step 4. パワポへの反映

`assets/企業概要書_テンプレート.pptx` を複製（`im_builder.open_template()`）し、**業種に合わせてページを削除・転用・追加**してから、各ページに貼付範囲を貼る（`im_paste.paste_range`）。
リード文は `set_lead`、Commentはテンプレートの既存の枠に `fill_comment` で書く（≪見出し≫10pt太字・本文9pt、鳥塚準拠）。
ページ構成と各ページで言うべきことは `references/im-structure.md`、デザイン仕様・配置の目安・業種別のページ構成は `references/im-design.md`。
PowerPointファイルを壊さずに編集する手順は `references/pptx-ops.md`（既存の表の編集・複製は `scripts/pptx_table.py`）。**スライドの追加・削除・表の行数変更をする前に必ず読むこと。**

作る前に**構成案（ページ一覧と各ページの一言メッセージ）**を決める。表は1枚15〜18行までとし、超えるなら内容で分割する。
依頼者が編集した最新版を受け取ったら、それを起点にして該当箇所だけを差し替える。作り直すと依頼者の修正が消える。

### Step 5. 案件特有の対応

会社分割スキーム、事業別の制作実績ページ、商流図など、案件ごとに必要なページを追加する。
会社分割案件の場合は `references/company-split.md`、不動産（代表者個人名義の事業用地、担保、借地・貸地）がある場合は `references/real-estate.md` を読むこと。
ノンネームシートは `references/nonname.md`（`nn_builder.check_anonymity()` を必ず通す）。

### Step 6. 検証

納品前に必ず以下を通す。ここを飛ばすと、数式エラーが残ったExcelや、文字がはみ出したスライドが客先に出る。
pptx/xlsx スキルの配置先は環境により `/root/.claude/skills/…`（synced配下を含む）か `/mnt/skills/public/…`。`find / -name validate.py -path '*pptx*'` で確認してから使う。

```bash
# 未導入なら（Impress と Calc の両方が要る）
apt-get install -y -q libreoffice-impress libreoffice-calc poppler-utils

# Excel：数式エラー0件を確認。recalc.py は対象を「その場で」書き換えるため必ずコピーに対して実行する
cp <案件マスター.xlsx> /tmp/chk.xlsx && python <skills>/xlsx/scripts/recalc.py /tmp/chk.xlsx 300

# PowerPoint：スキーマ・関係・チャートの検証
python <skills>/pptx/scripts/office/validate.py <概要書.pptx> --original <元ファイル.pptx>

# PowerPoint：全頁を描画して一覧画像で目視（必須。文字幅の計算だけで判断しない）
python .claude/skills/ma-deal-docs/scripts/render_check.py <概要書.pptx> <出力フォルダ>

# 社内限情報の混入チェック（案件固有の禁止語＝他社仲介名・NG先・前回価格等を引数に渡す）
python .claude/skills/ma-deal-docs/scripts/check_confidential.py <概要書.pptx> <禁止語…>
```

```python
# 表の構造チェック（ID重複・改行残存・tc順序違反・列数不一致・shape id重複 が0件であること）
import sys; sys.path.insert(0, '.claude/skills/ma-deal-docs/scripts')
from pptx_table import check_tables
print(check_tables(Presentation('after.pptx')) or '問題なし')

# 旧版との差分（表の中身も比較する）。変更したスライドだけが出ることを確認して報告する
def sig(s):
    return [('T:' + '|'.join(c.text for r in sh.table.rows for c in r.cells)) if sh.has_table
            else sh.text_frame.text for sh in s.shapes if sh.has_table or sh.has_text_frame]
a, b = Presentation('before.pptx'), Presentation('after.pptx')
print('変更スライド:', [i+1 for i, (x, y) in enumerate(zip(a.slides, b.slides)) if sig(x) != sig(y)])
```

数字を直したら、古い数字が残っていないか**概要書・マスター・確認リストの全文を検索**する（リード文・ポイント欄・注記・合計・組織図の箱・他ページに波及している）。

## 守るべきこと

### フォーマット

- 概要書・評価書・ノンネームとも**テンプレートの複製以外の方法で作らない**
- `strip_red_banners()` と `fix_broken_pictures()` を毎回呼ぶ。前者を忘れると社内メモが買手に出る。後者を忘れるとPowerPointが「修復が必要」と表示する
- 報酬体系ページ（概要書テンプレ35）、評価書の「株価評価にあたっての注意点」（テンプレ3）は削除も改変もしない

### 数値の一貫性

- 概要書の調整後EBITDAと評価書の正常収益力は、**同じ調整方針**で算定する。方針を変えるなら両方変える
- 分割後BSは「簿価ベース（対外説明資料用）」と「修正後BSベース（評価用）」で必然的に差が出る。**差が出ること自体は正しい**が、どちらの基準かを資料上に明記する
- 端数処理で合計が一致しない場合は、無理に数字をいじらず「※千円未満の端数処理により合計が一致しない場合があります」と注記する

### 事実と推測の区別

概要書は買手に渡る。書いた内容は後で必ず検証される。

- 面談で確認できた事実、資料から読み取れる事実、そこから合理的に導ける推測、まだ何も分かっていないこと、をはっきり区別して書く
- 推測を書くときは「〜と推察」「〜と想定」「（仮説）」と明示する
- 未確認のまま断定すると、DDで矛盾が出て売主・買手双方の心証を損なう。「要確認」と書いてあるほうが誠実で、結果的に信頼される
- **仮説は隠さず図解する。**ヒアリングしたい論点ほど、仮説と実績を並べて資料に載せると相手が答えやすくなる

### 概要書に載せてはいけない情報

面談議事録には内部限の情報が混ざっている。以下は概要書・買手向け資料に一切入れない：

- 他社仲介の併走状況、過去の仲介会社への不信感、過去のDDブレイク経緯、前回プロセスの価格
- 紹介料・報酬・テール条項の取り決め、アドバイザリー契約の送付先
- 関係者の人物評、NG先・ネームクリアの方針
- ショートリスト・ロングリスト、必要資料一覧の進捗などの社内進行管理

これらは案件マスター `その他` シートの「プロセス関連（社内確認事項）」やヒアリング項目一覧の同名セクションに隔離し、「本項は社内確認事項であり、買手候補への開示資料には記載しない」と明記する。納品前に `check_confidential.py` で検査する。

### 議事録を受け取ったときの進め方

「議事録を踏まえて概要書の更新箇所を指摘して」と言われたら、いきなり直さず、まず**概要書を通しで読んで**から突き合わせる。指摘は優先度で層に分ける：

1. 現状の記載のままだと買手に誤解を与えるもの（スキーム変更、譲渡条件、非事業用資産の扱い）
2. 追記したほうがよいもの（収益モデル、取引条件、キーパーソン）
3. 新規ページの提案
4. 概要書には載せない内部限情報
5. 既存資料と議事録の齟齬（＝次回ヒアリング項目）

5は捨てずに**ヒアリング項目一覧（Word）として成果物化する**。作り方は `references/hearing-list.md` を読むこと。

## バックアップと他のチャットでの利用

- このスキル一式はリポジトリの既定ブランチに置く（新しいチャットはここから読み込まれる）。改良したら既定ブランチへも反映する
- `.claude/hooks/format-guard.py`（UserPromptSubmit）が「概要書」「評価書」「ノンネーム」等の依頼を検知し、上記の手順を自動で注入する
- claude.ai の通常チャットで使うときは、スキル一式のzip（`ma-deal-docs.zip`）を 設定 → 機能 → スキル からアップロードする
