# M&A案件資料 作成スキル（案件マスター起点）

## このスキルの中心的な考え方

案件資料は**案件マスター（Excel）が唯一の数値のソース**であり、パワポ・ワードはその表示層にすぎない。

数字をパワポに直接打ち込むと、評価書と概要書で調整後EBITDAが食い違う、分割後BSと商流図で承継額が違う、といった事故が必ず起きる。実際に起きる。だから順序は常に **①案件マスターを直す → ②パワポに貼る → ③案件特有のページを個別対応** とする。

依頼が「概要書のこのページだけ直して」であっても、その数字がマスター由来なら**先にマスターを直す**。マスターを飛ばしてパワポだけ直すと、次に誰かがマスターから貼り直した瞬間に修正が消える。

## 全体ワークフロー

### Step 1. 受領資料の棚卸しと転記

決算書・登記簿・給与台帳・取引先実績・契約書等を読み、案件マスターの該当シートへ転記する。
シート構成と転記先の対応は `references/master-sheets.md` を読むこと。

転記時の原則：

- **数値は円単位で入力する。**表示形式が千円単位に設定済みのため、千円で入れると1000倍ずれる
- **文字は游ゴシック、数字はArial、細かい備考は游ゴシック Medium。**タイトル・合計欄は太字
- **確認できていないことは「要確認」と書く。**推測で埋めない。画像PDFでOCRできない、資料が未受領、といった事情はそのままシートに残す。後工程（評価書のコメント、ヒアリング項目一覧）でそのまま使える資産になる
- 転記後は必ず**借貸一致とPL整合のチェックセル**（`BS(借方)!C63` 等の `EXACT()` 行）が TRUE であることを確認する

### Step 2. 評価パート（VR→ セクション）の作成

時価純資産と正常収益力を算定する。詳細な手順・調整の考え方・数式は `references/valuation.md` を読むこと。

大まかには、修正BSで資産負債を時価評価し、修正PL/修正SGAで正常収益力を算定し、年買法（コストアプローチ）とEV/EBITDAマルチプル法（マーケットアプローチ）で株式価値レンジを出す。

### Step 3. IMパート（IM→ セクション）の作成

会社概要・PLハイライト・BSハイライト・取引先・仕入先・従業員等を埋める。ここが概要書の各ページの原本になる。

### Step 4. パワポへの反映

既存の概要書テンプレート（前回案件のファイル）を複製して中身を差し替える。ページ構成と各ページの作り方は `references/im-structure.md` を読むこと。
PowerPointファイルを壊さずに編集する具体的な手順・落とし穴は `references/pptx-ops.md` にまとめてある。**スライドの追加・削除・表の行数変更をする前に必ず読むこと。**

### Step 5. 案件特有の対応

会社分割スキーム、事業別の制作実績ページ、商流図など、案件ごとに必要なページを追加する。
会社分割案件の場合は `references/company-split.md` を読むこと。

### Step 6. 検証

納品前に必ず以下を通す。ここを飛ばすと、数式エラーが残ったExcelや、文字がはみ出したスライドが客先に出る。

```bash
# Excel：数式エラー0件を確認（LibreOffice Calcが必要）
python /root/.claude/skills/xlsx/scripts/recalc.py <案件マスター.xlsx> 300

# PowerPoint：スキーマ・関係・チャートの検証
python /root/.claude/skills/pptx/scripts/office/validate.py <概要書.pptx> --original <元ファイル.pptx>

# PowerPoint：レンダリングして目視（文字はみ出し・重なりの確認）
soffice --headless --norestore -env:UserInstallation=file:///tmp/lo-qa --convert-to pdf --outdir . deck.pptx
pdftoppm -jpeg -r 110 deck.pdf page
```

既存ページを触っていないことを主張するなら、実際に差分を取って確認する：

```python
from pptx import Presentation
a, b = Presentation('before.pptx'), Presentation('after.pptx')
diff = [i+1 for i,(x,y) in enumerate(zip(a.slides, b.slides))
        if [s.text_frame.text for s in x.shapes if s.has_text_frame]
        != [s.text_frame.text for s in y.shapes if s.has_text_frame]]
print('変更スライド:', diff)
```

## 守るべきこと

### 数値の一貫性

- 概要書の調整後EBITDAと評価書の正常収益力は、**同じ調整方針**で算定する。方針を変えるなら両方変える。片方だけ変えると、買手が概要書の数字に倍率を掛けた瞬間に評価書のレンジと乖離する
- 分割後BSは「簿価ベース（対外説明資料用）」と「修正後BSベース（評価用）」で必然的に差が出る。**差が出ること自体は正しい**が、どちらの基準かを資料上に明記する
- 端数処理で合計が一致しない場合は、無理に数字をいじらず「※千円未満の端数処理により合計が一致しない場合があります」と注記する

### 事実と推測の区別

概要書は買手に渡る。書いた内容は後で必ず検証される。

- 面談で確認できた事実、資料から読み取れる事実、そこから合理的に導ける推測、まだ何も分かっていないこと、をはっきり区別して書く
- 推測を書くときは「〜と推察」「〜と想定」「（仮説）」と明示する
- 未確認のまま断定すると、DDで矛盾が出て売主・買手双方の心証を損なう。「要確認」と書いてあるほうが誠実で、結果的に信頼される
- **仮説は隠さず図解する。**ヒアリングしたい論点ほど、仮説と実績を並べて資料に載せると相手が答えやすくなる（例：ロイヤリティ料率20%という発言に対し、実績の支払計上額と売上高比を併記して差の説明を求める）

### 概要書に載せてはいけない情報

面談議事録には内部限の情報が混ざっている。以下は概要書・買手向け資料に一切入れない：

- 他社仲介の併走状況、過去の仲介会社への不信感、過去のDDブレイク経緯
- 紹介料・報酬の取り決め、アドバイザリー契約の送付先
- 関係者の人物評
- ショートリスト、必要資料一覧の進捗などの社内進行管理

これらはヒアリング項目一覧の「プロセス関連（社内確認事項）」等に隔離し、そのセクションに「本項は社内確認事項であり、買手候補への開示資料には記載しない」と明記する。

### 議事録を受け取ったときの進め方

「議事録を踏まえて概要書の更新箇所を指摘して」と言われたら、いきなり直さず、まず**概要書を通しで読んで**から突き合わせる。指摘は優先度で層に分ける：

1. 現状の記載のままだと買手に誤解を与えるもの（スキーム変更、譲渡条件、非事業用資産の扱い）
2. 追記したほうがよいもの（収益モデル、取引条件、キーパーソン）
3. 新規ページの提案
4. 概要書には載せない内部限情報
5. 既存資料と議事録の齟齬（＝次回ヒアリング項目）

5は捨てずに**ヒアリング項目一覧（Word）として成果物化する**。買手から必ず来る質問を先回りして論点化しておくと、トップ面談の質が上がる。作り方は `references/hearing-list.md` を読むこと。
