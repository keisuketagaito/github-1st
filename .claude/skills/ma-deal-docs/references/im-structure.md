# 企業概要書（IM）の作り方 ― 当社フォーマット

## 鉄則：ゼロから作らない

**概要書は必ず `assets/企業概要書_テンプレート.pptx` を複製して作る。**
python-pptx で白紙から組み立ててはいけない。テンプレートにはマスター・レイアウト・
テーマ色・ロゴ・ヘッダー帯・Confidential表記・ページ番号が入っており、
これを再現することはできない。再現しようとすると「フォーマットが全く違う」と必ず言われる。

```python
import sys
sys.path.insert(0, '.claude/skills/ma-deal-docs/scripts')
from im_builder import *

prs = open_template()          # テンプレートを一時ファイルへ複製して開く
keep_slides(prs, [...])        # 使う頁だけ残す（1始まり）
duplicate_slide(prs, i, after=j)   # 足りない頁は複製して増やす
strip_red_banners(prs)         # 社内向けの赤帯を全削除（買手に出すので必須）
fix_broken_pictures(prs)       # テンプレ既知の壊れた画像参照を除去（必須）
```

`strip_red_banners()` と `fix_broken_pictures()` は**毎回必ず呼ぶ**。
前者を忘れると「提案するとき、注意喚起してますか？」等の社内メモが買手に出る。
後者を忘れると中扉5枚の壊れた参照が残り、PowerPointが「修復が必要」と表示する
（テンプレート自体が持っている不具合であり、`validate.py` で検知できる）。

## ページ枠（`本編1` レイアウト）

全ての本文ページが同じ骨格を持つ。座標はテンプレート実測値。

| 要素 | 位置 (x, y, w, h) | 書式 | 設定関数 |
|---|---|---|---|
| タイトル | (0.34, 0.20, 8.53, 0.37) プレースホルダ idx=0 | テーマ既定 | `set_title()` |
| 字幕（リード文） | (0.50, 0.91, 10.70, 0.26) プレースホルダ idx=1 | テーマ既定 | `set_lead()` |
| セクション名（右上） | (9.15, 0.28, 2.17, 0.20) テキストボックス | 12pt 太字 | `set_section()` |
| 本文領域 | y = 1.51 〜 7.20 | | |
| 注記（最下部） | (0.34, 7.25, 10.85, 0.35) | 7.5pt `5A6670` | `note()` |

2カラム構成の標準幅：左 x=0.34 幅6.61 ／ 右 x=7.06 幅4.29。
表を広く使う場合は左 幅5.30 ／ 右 x=5.88 幅5.47。全幅は 0.34 から 11.01。

**字幕（リード文）が最重要。** 「何が書いてあるか」ではなく「**だから何なのか**」を
1〜2行で断言する。全角110字を超えると3行になり本文と重なる。

- 悪い例：「売上高の推移は下表のとおりです」
- 良い例：「売上高は4期で25.4％減少し営業赤字。一方で年間7,012千円の減価償却費を戻した調整後EBITDAは6,801千円を確保」

## 品質基準

**鳥塚案件（260924）の水準を基準とする。** 要点は「テンプレートの穴を埋める」のではなく、
**その案件で何が論点になるかを考えて必要な頁を作る**こと。鳥塚では以下を追加している：

- 生産サイクル（季節性のある事業の、年間を通じた供給体制の図解）
- 参考｜天然と人工種苗の特性・用途比較（表＋位置づけボックス＋ポイント帯）
- 仕入・販売における価格形成の仕組み（価格競争に晒されにくい理由の説明）
- 不動産の担保設定・権利関係（担保一覧と債務者の整理）
- 不動産詳細を法人所有／社長所有に分けて筆単位で開示
- 許認可一覧（参入障壁の裏付け）

慈久庵案件（261007）では、同じ考え方で次を追加している：

- そばづくりの工程（6工程の図解＋「設備を買っても再現できないもの」の整理）
- 物販・通信販売の商品一覧（店頭以外の導線と、許認可・製造場所の論点）
- 知的財産・許認可（商標4件の権利範囲が買手の最大の関心事になるため独立頁に）
- 外部評価・メディア掲載（受賞・掲載に加え「同業のつくり手が仕入れに来る」点を明示）
- 稼働拡大による売上・利益インパクト（営業日×日商のシナリオ表＋EBITDAの組み立て）
- 買手が承継するもの（ブランド・商標・レシピ・店舗・産地との関係の承継可否）

### 論点は「打ち手」とセットで出す

概要書は買手に「買った後どうなるか」を考えてもらうための資料であって、
リスクの一覧表ではない。コストや弱点を書くときは、**同じ頁か隣の頁に、
それを吸収する打ち手と、承継によって手に入るものを必ず並べる。**

| 書き方 | 買手の受け取り方 |
|---|---|
| ✗ 「代表者は無報酬のため、新体制では人件費が必要」だけ | 利益が出ない会社に見える |
| ✓ 人件費を置いたうえで、稼働拡大シナリオ・承継する資産・買手タイプ別の見え方を併記 | 自社ならどう運営するかを考え始める |

数字は必ず案件マスターに**シナリオとして数式で持たせる**（慈久庵では
PLハイライト 40〜51行に限界利益率とシナリオA/B/Cを置いた）。
パワポに直書きすると、前提を変えたときに資料間で食い違う。
仮説は「仮説」と明示し、前提（限界利益率の導出・日商の出所）を同じ頁の注記に書く。

案件ごとに「買手が必ず聞いてくること」を先回りして頁にする。例：

| 案件の性格 | 作るべき頁 |
|---|---|
| 季節変動が大きい | 月別売上高、繁閑差と運転資金 |
| 許認可が参入障壁 | 許認可一覧、更新時期、承継可否 |
| 不動産が重い | 不動産詳細（筆単位）、担保設定、法人／個人の切り分け |
| オーナー依存が強い | 属人性の整理（「事実」と「備え」を併記）、引継ぎ計画 |
| 特定取引先に依存 | 取引先別推移、契約条件、COC条項 |
| 稼働に余力がある | 稼働率と拡大余地の感応度試算（仮説と明示） |

## ページ別のポイント

### 基本情報（テンプレ5）

左に `会社概要` の表（紺帯＋2列表、項目幅1.35）、右に `本件のポイント`
（紺帯＋白カード5枚、幅4.40・高さ0.98）。カードは「見出しを青太字10pt＋本文9pt」。
**5枚目は必ず「論点（要確認）」にする。** 良い話だけ並べた概要書は信用されない。

### 財務ハイライト（P/L）（テンプレ6）

左に5期の推移表（幅6.61）＋売上高の棒グラフ、右上に `Comment`、右下に `【調整項目】`。

- Comment は ≪売上高≫≪売上総利益≫≪営業利益≫≪見通し≫ の見出し付きで、
  数字が**動いた理由**を書く。「大型案件により拡大」のような根拠の薄い説明ではなく、
  PL上で検証できる要因（数量・単価・原価率・販管費）で説明する
- 【調整項目】は ≪科目群≫ごとに調整理由を列挙し、最後に
  `✓ 調整後EBITDA（過去3期平均）は◯◯千円` と結論を置く
- 調整項目が無い案件なら「無い」と書き、無い理由を書く
- 単年が極端に低い場合は3期平均が実力を下回るため、**直近2期平均も併記**する

### 財務ハイライト（B/S）（テンプレ7）

左にB/S、右上に `Comment`、右下に `【時価修正】`。
時価純資産を算定していないなら「着眼点」として論点だけ挙げ、未了であることを明記する。

### 譲渡希望条件（テンプレ8）

テンプレートの4バンド（条件1スキーム／条件2希望価格／条件3付帯条件／その他譲渡理由）の
図形をそのまま使い、右側のテキストボックスだけ差し替える。**図形を作り直さない。**
テンプレート側に箇条書き記号が設定されているので `set_text(..., bullet=False)` を使う。
代表者の継続関与の意向は付帯条件に埋もれさせず独立した行で書く。買手の最大の関心事になる。

### 商流（テンプレ10）

中央に対象会社（紺）、左に主要仕入先、右に主要販売先。
対象会社ブロックは**事業ライン別**に分ける。ブロック間の矢印には流れの名前を書く。
関係会社・関係先との取引は色を変えて（赤系）区別し、論点であることを示す。

### 特徴（テンプレ12）

`feature_bands()` で「特徴／強み／成長性」の3バンド。
各バンドは見出し14pt太字＋本文10.5pt。見出しは体言止めで言い切る。

### 要確認事項・ネクストステップ（テンプレ34を転用）

分野・確認事項・優先度（高／中）の3列。**案件マスター「その他」シートと必ず一致させる。**
買手向けに出せない内部限情報（契約状況・価格の温度感・社内進行管理）は絶対に載せない。

## 写真の扱い

**概要書は写真で読ませる。** 鳥塚案件が強いのは、文章と数字だけでなく
現場の写真が入っているためで、店舗型・現場型の案件ほど写真の有無が印象を左右する。

```python
photo_tile(s, f'{PH}/外観01.jpg', 0.34, 1.62, 3.44, 2.30, '店舗外観')
n = photo_strip(s, [(f'{PH}/商品_乾麺.jpg', '乾麺'), ...], 0.34, 5.16, 6.98, 1.18)
```

| 原則 | 理由 |
|---|---|
| 枠を先に決めて中央トリミングする | 縦横比の違う写真を並べると天地が揃わず、素人の資料に見える |
| ファイルが無ければ何も描かない | 写真の受領待ちでも頁として成立させる。空枠を買手に出さない |
| キャプションを必ず付ける（8pt `5A6670`） | 何の写真か分からない画像は情報にならない |
| 案件フォルダに `写真/README.md` を置く | 売主・担当者に「何をどのファイル名で撮って送るか」を指示できる |

写真が無い段階では、まず**写真なしで成立する頁**を作る。そのうえで
`写真/README.md` に「このファイル名で置けばこの頁に入る」を書き、
届いた順にビルドスクリプトを再実行する。

### 掲載誌・書籍の写真（著作権）

雑誌の誌面や書籍のページを複写した画像は発行元の著作権が及ぶため、
買手候補へ配布する概要書に載せるには許諾が要る。許諾が取れるまでは
**誌名・掲載年・内容を文字情報として記載**するにとどめる。

一方、**受賞盾・ステッカー等の店内掲示物を当社が撮影した写真**は
この制約を受けない。外部評価を可視化したいときはこちらを優先して使う。

## 検証（納品前に必ず通す）

```bash
# 案件マスターの数式を再計算してキャッシュ値を書き戻す（数式を触ったら必ず）
python .claude/skills/ma-deal-docs/scripts/recalc.py <案件マスター.xlsx>
```

パワポ側は `openpyxl.load_workbook(..., data_only=True)` でキャッシュ値を読むため、
数式を書いただけでは `None` が入る。`recalc.py` は LibreOffice Calc を
「読込時に常に再計算」の設定で起動し、再計算結果を同じファイルへ書き戻す。

```bash
# スキーマ・関係・チャートの検証（テンプレ由来のエラーを差し引く）
python /mnt/skills/public/pptx/scripts/office/validate.py <概要書.pptx>

# レンダリングして全頁を目視（文字のはみ出し・重なり）
soffice --headless --norestore -env:UserInstallation=file:///tmp/lo-qa \
  --convert-to pdf --outdir . deck.pptx
pdftoppm -jpeg -r 80 deck.pdf page
```

見るべきは**文字のはみ出しと重なり**。特に、

- 字幕が3行になって下のコンテンツと重なる
- Comment ボックスのテキストが枠からあふれる
- 表の行が増えて最下部の注記と重なる（注記は固定位置なので表の高さを変えたら必ず動かす）

游ゴシックはLibreOfficeで代替フォントに置換され、PowerPoint実機より1〜2割広く
描画される。**LibreOfficeで収まっていれば実機でも収まる**ので、この基準で詰める。

赤帯が残っていないかも必ず確認する：

```bash

from pptx import Presentation
p=Presentation('deck.pptx')
for i,s in enumerate(p.slides,1):
    for sh in s.shapes:
        if sh.has_text_frame:
            for para in sh.text_frame.paragraphs:
                for r in para.runs:
                    try:
                        if r.font.color and str(r.font.color.rgb)=='FF0000':
                            print('赤字残り', i, r.text[:40])
                    except Exception: pass
"
```
